# Changelog

All notable changes are documented here. The format follows
[Keep a Changelog](https://keepachangelog.com/en/1.1.0/) and the project uses
[Semantic Versioning](https://semver.org/) with lockstep versions across all packages
(see [ADR 0005](docs/adr/0005-single-brand-monorepo-lockstep-versioning.md)).

Each release heading states the supported Lua version.

## [Unreleased] — Lua 5.5

### Added

- feat(tools): two rules for code examples (owner request, 2026-11-12; `docs/architecture/documentation.md`, "Code examples"). `check-examples` reports a line holding a comment longer than 80 characters in `packages/*/examples/`, `examples/` and the Lua blocks of the website pages, unless the line above holds `check-examples: allow-long-comment`. The examples tests of every package run through one shared runner, `tools/harness/examples.lua`, which requires each printed line to be expected by a `-- Prints:` block directly under the line that printed it. Every example and the website pages that include them follow both rules.
- test(kernel, http, log, config): every statement of the production checklist page about hecate's behaviour is pinned by a test (logger built from the logging keys, the records written and not written, redaction, secrets, `on_response`, limits, signals); each test names the page section it backs.
- docs(website): how-to "Before going to production", a checklist of the environment, error details, logging and redaction (by field name, never free text), secrets, the access log (strip the query), limits, workers and shutdown.
- feat(benchmarks): network scenarios `plaintext` (`http.Server` alone, keep-alive, optional pipelining) and `kernel-json` (one `kernel.Application` route represented and encoded as JSON), driven by an open-loop HTTP/1.1 load generator (`benchmarks/lib/http_load.lua`); `benchmarks.yml` compares both with the base, next to `tcp-echo`. The deferred performance findings RE2, J4, the `router` findings and the `schema` findings P5 and P6 were measured and kept, P6 provisionally (`docs/reviews/phase-2-benchmarks.md`). perf(log): `Logger:with_context` copies the severity ordinal into the child instead of resolving it again (LO4, about 29 % cheaper). fix(schema): the `validate` micro-benchmark declares `schema.Representable` on its classes again.
- `hecate.reactor`: `reactor.offload(fn, ...)` runs a self-contained Lua function (no upvalue but `_ENV`) on the libuv thread pool, in the separate Lua state of a pool thread, and suspends the caller until it returns (roadmap item `reactor` follow-up, OQ-27; specification `docs/architecture/concurrency.md`, "Offload"). Arguments and results are copied by an own encoding (`nil`, booleans, numbers with their subtype, strings, plain tables up to 100 levels), without luv's limit of nine values; an error of the function is raised as the new `reactor.OffloadError` (`context.reason`, the pool-thread traceback, the `code` of a framework error); the function runs in a fresh environment per call; a cancelled caller is released at once and the late result discarded, and `Reactor:run` waits for every offloaded function before returning (luv crashes when the Lua state closes with work in flight). Micro-benchmark `reactor/offload`. At most `max_offloads` functions (a `Reactor` option; default the pool size minus one, at least 1) are on the pool at once; the other calls wait in a first-in-first-out queue kept in Lua, where a cancelled caller is removed and its function never runs (owner decisions on OQ-119). The choices were decided by the owner in OQ-119. Tested example `hecate.reactor.offload` and the guide `how-to/offload-cpu-bound-work.md`.
- docs(examples): `examples/hello` logs each response on the standard error stream (method, path without the query string, status, bytes, duration) through the `on_response` hook of `http.Server`; its README installs `luv` into `.hecate/rocks` (`luarocks --tree .hecate/rocks install luv 1.53.0-0`), which the bootstrap does not install, contrary to what it said.
- docs(examples): `examples/hello` uses the meta-module `hecate` (`hecate.Application`, `hecate.Controller`, `hecate.routes`, `hecate.respond`, `hecate.problem`); its README gives run commands that work as written (`build-native json` and `build-native http` separately, the `LUA_PATH` and `LUA_CPATH` entries).
- test(examples): `examples/hello` shows that a graceful shutdown drains a request in flight (Phase 2 exit criterion), in process and in a worker of two: a request in flight (`Expect: 100-continue`, content not sent yet) is answered with `Connection: close` once new connections are refused and every server has begun its shutdown; the workers test checks that both workers served.
- fix(tools): `affected` maps a change to an example (`examples/<name>/`, Markdown excepted) to `kernel`, so CI runs the example on the three platforms; a change to an example alone ran none of its tests.
- feat(reactor): `Peer:send` takes `options.keep_open`, which leaves a handed-over stream open in the sender for the caller to close.
- fix(kernel): the primary keeps each handed-over connection open until the worker answers `received` (a new message), and closes what is still held when the worker's message pipe ends or it exits; fixes connections lost during a rolling reload on macOS (OQ-118; ADR 0023 Decision 5 amended).
- feat(kernel): a worker logs the connections it drops: `control_failed` (`error`) when its message pipe to the primary breaks or is violated (it was a silent stop), `hand_over_discarded` (`warning`, `count`) for the connections still queued when it stops; `HandOverListener:close()` returns how many queued connections it closed; a worker sends its final `counters` when it has stopped serving and the primary logs `hand_over_unaccounted` (`warning`) when a worker exits having accepted fewer connections than were handed over to it.
