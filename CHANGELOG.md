# Changelog

All notable changes are documented here. The format follows
[Keep a Changelog](https://keepachangelog.com/en/1.1.0/) and the project uses
[Semantic Versioning](https://semver.org/) with lockstep versions across all packages
(see [ADR 0005](docs/adr/0005-single-brand-monorepo-lockstep-versioning.md)).

Each release heading states the supported Lua version.

## [Unreleased] — Lua 5.5

### Added

- `hecate.reactor`: scope-local context (ADR 0025): `with_local(key, value, fn, ...)` and `local_value(key)` (also `reactor["local"]`, OQ-56): immutable bindings inherited at `fork`, `detach` and `Scope:fork` from the creator, removed on return or error. `hecate.log`: `log.bind(fields, fn, ...)` and a default `context_provider` that reads it, so a record logged by a forked computation carries the bound fields.

- `hecate.doc`: Markdown and syntax highlighting come from a Rust native module (`packages/doc/native`, ADR 0022: comrak 0.52 for complete GFM, syntect 5 with the two-face syntaxes through `mlua`; `lua tools/run.lua build-native doc`, built and linted in CI on the three platforms, covered by `cargo audit` and `cargo deny`). The in-house Markdown renderer, inline renderer and lexers are retired. Callouts are GFM alerts (`> [!NOTE] Title`, `TIP`, `IMPORTANT`, `WARNING`, `CAUTION`): the `::: name` containers of the first slice are gone and the pages of `website/` are converted. Highlighted code uses `hl-` scope classes mapped to the brand tokens in the theme. Raw HTML is shown as text and comments are dropped, as before. The 652 examples of the CommonMark 0.31.2 specification and the 22 extension examples of the GFM specification run as a test through the module (`fetch-fixtures doc`, pinned commits, OQ-37). The licences of the embedded syntaxes are audited (all permissive, recorded in THIRD_PARTY_NOTICES). Still to do: a Lua 5.5 syntax definition (`global`, `---@` annotations), the prebuilt binary rocks.
- `hecate.log`: generated code reference (`log` added to the reference generator's default packages) and micro-benchmark `packages/log/benchmarks/logger.lua` (disabled, enabled and `AsyncSink` call).
- `hecate.log`: `Logger` option `redact` (field names, case-insensitive, any depth) wraps the matching values of fields and context in a `Secret` before any sink sees them.
- `hecate.log`, review fixes: `AsyncSink:flush` after `close` returns instead of waiting for a task that is gone; `ConsoleSink` escapes control characters in field keys and logger names (a key could forge a line); `JsonLinesSink` keeps a record whose message is not valid UTF-8, with the bytes escaped, instead of losing it; a `context_provider` that raises or returns a non-table is counted in `failures()` and no longer fails the logging call; `FileSink` raises when a write fails (a `Logger` counts it) instead of losing the record silently; `MemorySink` with a capacity is a ring buffer (constant time per write).
- `hecate.log`, step 1: the eight RFC 5424 severities (`Severity`, `severity_code`), `Record`, `Logger` with a threshold, per-logger context (`with_context`, `context_provider`) and synchronous sinks, `MemorySink`, `JsonLinesSink` (one JSON object per line, built on `hecate.json`) and `Secret` (never rendered), step 2 (part): `ConsoleSink` (human-readable lines) and `FileSink` (JSON lines appended to a file, synchronous). step 3 (part): `LimitedSink`, a decorator sink that samples and rate-limits (token bucket) records less urgent than an exempt severity and counts what it drops. step 4 (part): `AsyncSink`, a decorator sink that queues records (bounded, overflow dropped and counted) and writes them from a detached task driven by a `Semaphore`, so a log call never suspends. Open points in OQ-55 (the reactor has no scope-local context yet; decided in ADR 0025, to be implemented). Documentation: how-to guide `log-structured-records` and two tested examples.
- `hecate.json`: tested examples (`packages/json/examples`, run by `tests/unit/examples_test.lua`) and the how-to guide "Encode and decode JSON" on the website.
- `hecate.doc`: `json` joins the default packages of the generated code reference (`gen-reference`).
- `hecate.json`: the native decoder reports a rejected text from the error of yyjson (reason, message, byte position) instead of parsing it again with the pure-Lua decoder: a 16 MiB array with a trailing comma fails in 0.35 s instead of 6.2 s; a text nested beyond `max_depth` is refused before yyjson runs by a one-pass count of brackets (16 MiB of `[` takes 19 MB instead of 291 MB). Limits that come from yyjson, documented in the README: the message does not say what was expected, a duplicate member name has no position, and a text with several defects may be reported at another one (OQ-54, owner decision).
- `hecate.json`: `max_depth` is at most 1000 for `decode` and `encode` alike (it was 10000), with the same default and the same `max_size` on both sides; a text or value nested deeper is a `depth_limit` error (owner decision, OQ-54).
- `hecate.json`: the C converter recurses at most 1000 levels (it was 10000): a text nested deeper, with a larger `max_depth`, is decoded by the reference decoder instead of risking an overflow of the C stack (1 MiB on Windows; a 10000-level text crashed under a 512 KB stack); with `canonical`, an invalid UTF-8 member name that looks like a four-byte character raises `invalid_utf8` instead of a Lua error (native-code review).
- `hecate.json`: decode error messages echo at most 40 bytes of the input (member names and number literals), with control characters escaped, instead of the whole text (security review); OQ-54 records the cost of hostile input that the review measured and the owner decisions taken on it.

- `hecate.net` and `hecate.reactor` review round (nine reviewers, all findings addressed): `TlsStream` serialises `write` and `shutdown` under one mutex and closes the stream when a write or shutdown fails or is cancelled after the session accepted bytes (no leaked prefix, no interleaved concurrent writes); a reader is no longer held up by a writer blocked in back-pressure; cancellation is never swallowed; a closed `TlsStream`, `BufferedReader` or `BufferedWriter` raises `reactor.TransportError` (`EBADF`, stable `context.operation`) like `TcpStream`; a second concurrent reader, and a write after `shutdown` (`EPIPE`), raise; the native module no longer fails the end of the transport with "received plaintext buffer full" (rustls 0.23.46, found by reading its source); native TLS errors carry a kind taken from the `rustls::Error` variant (`context.reason`), ALPN names are validated, `Session` and `Config` have `close`/`__close`, native `read` reuses a scratch buffer and `write` takes an offset; `reactor.spawn` options `stdout`/`stderr = "ignore"` now take effect (the stdio table was built with an `and nil or` trap); the message pipe marker and descriptor no longer leak into grandchildren; message pipe frames with a stream attached to a frame that announces none, several streams on one frame, or a malformed or oversized frame raise `TransportError` `EPROTO` and close the peer; `Process:kill` treats `ESRCH` as success and validates the signal; Windows environment names merge case-insensitively; `TcpListener:accept` skips a connection whose peer already reset it; `keepalive_delay` must be a positive integer; "task" becomes "coroutine" and "channel" becomes "message pipe" in messages and docs.

- `hecate.doc`: the reference generator no longer crashes or renames members when a class has undocumented bare fields (the result depended on hash order); `tools`: `check-links` ignores links into a code reference that is not generated.
