| OQ-25 | decision | `reactor`, channels and synchronisation primitives (concurrency.md leaves these points open; each was implemented conservatively): (1) `Channel:receive` on a closed and drained channel raises `ClosedChannelError` (new in `core`) rather than returning a flag, and `close` is idempotent (returns whether it closed); (2) `select` takes channel operations (`Channel:receive_op()`, `Channel:send_op(v)`) next to futures, picks the first ready item in argument order (deterministic; Go picks at random, which avoids starvation of later items), and cancels only the futures it did not pick; (3) `Monitor` signalling follows Mesa semantics (the signaller keeps the monitor, waiters re-test their predicate), not Hoare's signal-and-urgent-wait; (4) `Semaphore:release()` adds a unit without a permit and has no upper bound; (5) a `Monitor` is not reentrant and is owned by a coroutine, whereas a `Mutex` has no owner; (6) the condition method is named `signal` after Hoare (1974), although the glossary discourages "signal" as a name for the condition concept. | `reactor` |
| OQ-26 | decision | `reactor`, I/O calls and `detach` (concurrency.md leaves these points open; each was implemented conservatively): (1) `detach(fn, ...)` forks into the application scope (the root scope of `Reactor:run`); a detached failure is observable only through its future and does not cancel the application scope, so an unobserved failure is silent until a logging hook exists; (2) file-system and process calls raise `hecate.reactor.IoError` (defined in `reactor`, not `core`; `context.errno` holds the libuv name such as `ENOENT`), whereas `core` has no I/O error class; (3) file-system requests are uncancellable once started (libuv cannot withdraw them); (4) all libuv I/O needs the real clock, a virtual-clock reactor refuses it; (5) `run_process` kills the child when cancelled. | `reactor` |
| OQ-29 | decision | `net`, buffered reader and writer (the specification leaves these open; each was implemented conservatively): (1) `read_line` strips the line feed and one carriage return before it, `read_until` strips only the delimiter; (2) a read that meets end of stream inside a record raises `EndOfStreamError` (a `NetworkError`) and keeps the bytes buffered, whereas end of stream on an empty buffer returns nil; (3) a record longer than `limit` (default 64 KiB) raises `core.ProtocolError`; (4) the writer is poisoned after a failed or cancelled flush, because the number of bytes sent is unknown; (5) `BufferedWriter:close` and `__close` discard unflushed bytes instead of flushing (OQ-23: no suspension in a close handler); (6) readers and writers do not own their stream; (7) each reader and writer serialises its operations with a `Mutex`. | `net` |
| OQ-30 | decision | `reactor`, TCP transport primitives (decided by OQ-28; the specification leaves these points open, each was implemented conservatively): (1) addresses are numeric only: `reactor.tcp_connect(host, port)` and `tcp_listen` do not resolve names, a host name raises `TransportError` with `errno = "EINVAL"` (superseded by OQ-32 (1)) (DNS is a later step); (2) cancelling `read` or `accept` leaves the handle open and loses no data or connection, whereas cancelling a `write`, `shutdown` or `tcp_connect` that has not completed closes the stream or handle, because libuv cannot withdraw the request and the number of bytes sent is unknown (consistent with OQ-29 (4)); (3) there is no timeout option, a connect or I/O is bounded by wrapping it in `reactor.deadline`; (4) defaults: `nodelay = true` (Nagle off), `keepalive = false` with a 60 s idle delay when enabled, listen `backlog = 128`; accepted streams inherit the listener options; (5) errors: use of a closed stream raises `TransportError` (a `core.NetworkError`, owner decision on OQ-32 (5)) with `errno = "EBADF"`, closing a stream or listener while a task waits on it wakes that task with `errno = "ECANCELED"` (libuv's name for a request cancelled by close, here also used for read and accept, which libuv does not report), and libuv callbacks that deliver a bare error name are normalised so `context.errno` is always the libuv name; (6) one task reads and one task accepts at a time (a second concurrent call raises `core.Error`), writes from several tasks are queued in call order; (7) a read error is sticky (raised again by later reads), an accept error is raised once; (8) `read(max)` returns what one receive delivered, at most `max` bytes, never an empty string, nil at end of stream; (9) a stream not closed explicitly keeps its libuv handle open until it is closed: there is no finaliser. | `reactor`, `net` |
| OQ-31 | decision | `reactor`, SIGPIPE: libuv leaves the default action, so a write to a connection closed by the peer would kill the process. Each real-clock `Reactor:run` therefore installs an unreferenced libuv signal handle for `SIGPIPE` (no-op handler, closed at the end of the run) so that the write fails with `EPIPE`/`ECONNRESET`. Effects: the handler is process-wide while a reactor runs and replaces any `SIGPIPE` disposition of the host program; `wait_signal("sigpipe")` shares it. Not applicable on Windows (handle not created); verified on Linux only until CI runs on the three platforms. | `reactor` |
| OQ-32 | decision | `net` and `reactor`, TCP streams and name resolution (step 3 of the `net` item; each point was implemented conservatively): (1) `reactor.resolve(host, { family? })` is a new suspending primitive over libuv `getaddrinfo` (OQ-28 option a extended to DNS); it returns every address in the system resolver's order, a cancelled call is released at once and the late result discarded, a failure is a `TransportError` (`errno` such as `EAI_NONAME`); (2) `net.connect` resolves, then tries the addresses one after the other and raises the last `TransportError`; there is no parallel connection attempt (RFC 8305, Happy Eyeballs) and no per-attempt timeout, the caller bounds the whole call with `reactor.deadline`; (3) `net.listen` binds to the first resolved address only; (4) the net-level option `family` (`inet` or `inet6`) is added to the reactor options; (5) `net.TcpStream` and `TcpListener` wrap the reactor objects and let the error propagate unchanged; decided by the owner (2026-10-13): a TCP failure is a network failure, so failures of TCP and name resolution are `reactor.TransportError`, a subclass of `core.NetworkError` (`context.errno` and `context.operation` kept), while `IoError` stays for the file system and processes; `core` has no multiple inheritance, so the two are siblings and a transport failure is not an `IoError` (6) `read`, `write` and `shutdown` have no `timeout` argument: the idiom is `reactor.deadline(seconds, fn, ...)`, and a write cancelled by a deadline closes the stream (OQ-30), a read cancelled keeps it; (7) `TcpStream:reader()`/`:writer()` create a new buffered wrapper per call, and several readers over one stream would split its bytes: one reader per stream is the rule, not enforced; (8) `getaddrinfo` runs on libuv's thread pool (default 4 threads): many slow resolutions can queue behind each other, no cache. | `net` |
