| OQ-25 | decision | `reactor`, channels and synchronisation primitives (concurrency.md leaves these points open; each was implemented conservatively): (1) `Channel:receive` on a closed and drained channel raises `ClosedChannelError` (new in `core`) rather than returning a flag, and `close` is idempotent (returns whether it closed); (2) `select` takes channel operations (`Channel:receive_op()`, `Channel:send_op(v)`) next to futures, picks the first ready item in argument order (deterministic; Go picks at random, which avoids starvation of later items), and cancels only the futures it did not pick; (3) `Monitor` signalling follows Mesa semantics (the signaller keeps the monitor, waiters re-test their predicate), not Hoare's signal-and-urgent-wait; (4) `Semaphore:release()` adds a unit without a permit and has no upper bound; (5) a `Monitor` is not reentrant and is owned by a coroutine, whereas a `Mutex` has no owner; (6) the condition method is named `signal` after Hoare (1974), although the glossary discourages "signal" as a name for the condition concept. | `reactor` |
| OQ-26 | decision | `reactor`, I/O calls and `detach` (concurrency.md leaves these points open; each was implemented conservatively): (1) `detach(fn, ...)` forks into the application scope (the root scope of `Reactor:run`); a detached failure is observable only through its future and does not cancel the application scope, so an unobserved failure is silent until a logging hook exists; (2) file-system and process calls raise `hecate.reactor.IoError` (defined in `reactor`, not `core`; `context.errno` holds the libuv name such as `ENOENT`), whereas `core` has no I/O error class; (3) file-system requests are uncancellable once started (libuv cannot withdraw them); (4) all libuv I/O needs the real clock, a virtual-clock reactor refuses it; (5) `run_process` kills the child when cancelled. | `reactor` |
| OQ-28 | decision | `net`, transport primitives (blocks TCP): ADR 0002 and `check-boundaries` allow only `reactor` to `require "luv"`, and "luv's callback API is wrapped once, in `reactor`, into suspending operations". `reactor` currently exposes no TCP, UDP, DNS or pipe handle, so `net` cannot build `TcpStream` or `TcpListener` without either (a) `reactor` gaining suspending transport primitives (conservative option, consistent with ADR 0002: for example `reactor.tcp_connect(host, port)`, `reactor.tcp_listen(...)`, with handle objects offering `read`, `write`, `shutdown`, `close`, built on `uv_call` and the same cancellation rules as `run_process`), or (b) an exception to the luv confinement rule for `net`, which needs an ADR amendment. Neither was implemented; the conservative option (a) is a `reactor` change, outside the `net` item. | `net` |
| OQ-29 | decision | `net`, buffered reader and writer (the specification leaves these open; each was implemented conservatively): (1) `read_line` strips the line feed and one carriage return before it, `read_until` strips only the delimiter; (2) a read that meets end of stream inside a record raises `EndOfStreamError` (a `NetworkError`) and keeps the bytes buffered, whereas end of stream on an empty buffer returns nil; (3) a record longer than `limit` (default 64 KiB) raises `core.ProtocolError`; (4) the writer is poisoned after a failed or cancelled flush, because the number of bytes sent is unknown; (5) `BufferedWriter:close` and `__close` discard unflushed bytes instead of flushing (OQ-23: no suspension in a close handler); (6) readers and writers do not own their stream; (7) each reader and writer serialises its operations with a `Mutex`. | `net` |
