# Open questions

Each entry is either a **decision** awaiting the project owner, a **research** task, or a
**spike → owner decision**: a spike report (`docs/spikes/`) with a recommendation, on
which the owner decides.
When resolved, record the outcome (ADR or specification update) and move the entry to
"Resolved" with a link.

This file is the source of truth. Every entry is mirrored by a GitHub issue labelled
`open-question` (and `oq:decision`, `oq:research`, `oq:spike` or `oq:limitation`, plus
`package:*`, and `due:phase-N` or `due:none`, the phase before whose end it must be resolved) whose title starts with the OQ number, created from the "Open question" issue
template: the issue is for discussion and tracking, and resolved entries have a closed issue.
When an entry is resolved, record only the final answer here (not the discussion), then close
its issue with a link to the pull request. These issues never carry `needs-decision` or
`blocked`, which the relay reads as a blocked roadmap item.

Decide when `schema` and `kernel` are specified (Phase 2); no conservative default is needed until then. **Owner answers, 2026-10-27:** the schema is tied to the class, and the route names which schema to validate against; the validator takes the HTTP method into account (a PATCH may carry partial content, so required attributes are relaxed for it; PUT and POST stay strict); an expected attribute missing from the content is nil in the instance, and validation fails only when the class attribute is not nilable; responses work the same way (an instance is encoded); raw access to the content stays available per route, at least for debugging. Clarified, 2026-10-27: "absent is nil" holds for POST and PUT (an absent nilable attribute is nil, an absent non-nilable one fails); for PATCH an absent attribute means unchanged, and an explicit `null` means clear (it fails if the attribute is not nilable). A route, or another schema, names the class itself (for example `schema.of(User)`; the names are illustrative, to be settled with the glossary), never a string class name. Validation, coercion and the OpenAPI emission all call that same function. The result is immutable, so it is called once and cached. A nested class property is emitted once under the class name (`$defs`, then an OpenAPI component). The PATCH variant is derived by the validator, not by the class: the function takes no argument. A response instance is encoded with the same schema. Cycles: resolution is lazy and memoized; `schema.of(User)` does not call `User.schema()` at declaration. The resolver keeps the set of classes being resolved and closes a cycle with a reference (`$ref` to a `$defs` entry, a late-bound slot in the validator), which also delivers the recursive schemas. A require cycle between modules is the user's to avoid by requiring inside `schema()`; to help, `schema.of` also accepts a module name as a string, loaded at first use (a module path, not a class name). An object graph with a cycle cannot be encoded: the encoder raises an error. Incoming JSON is a tree; the decoder depth limit bounds hostile depth (verified 2026-11-07: validation, coercion and build of a recursive schema handle the decoder maximum of 1000 levels, and a hand-built deeper table gets a depth_limit violation from the schema guard). Resolved 2026-11-03; implementation tracked in the `schema` roadmap item. |

### OQ-55 addendum — asynchronous sinks (corrected)

An earlier note said asynchronous flushing needed a public non-suspending wake from `reactor`. That was
wrong: `Semaphore:release()` never suspends and `reactor.detach` starts a computation that outlives the caller,
which is all a sink queue needs. `hecate.log.AsyncSink` is built on them, with no `reactor` change. Point (1)
of OQ-55 is decided by [ADR 0025](adr/0025-ambient-context.md) (Accepted):
`reactor.with_ambient(key, value, fn)` and `reactor.ambient(key)`, implemented (OQ-56 chose the name).

### OQ-56 — The name of the scope-bound context accessor

**Decided by the owner (2026-10-25).** ADR 0025 named the accessor `reactor.local`, which is a syntax error with dot
syntax because `local` is a reserved word of Lua. The word `local` is dropped everywhere (the accessor, the binder, the
internal field, the tests and the documents): the concept is the **ambient context**, with `reactor.with_ambient(key,
value, fn, ...)` and `reactor.ambient(key)`, matching the `ambient` module of `hecate.log`. ADR 0025 is amended and its
file renamed to `0025-ambient-context.md`. There is no second name.
