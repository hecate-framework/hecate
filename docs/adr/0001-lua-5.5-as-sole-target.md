# 0001 — Lua 5.5 as the sole target, 5.4 later through source lowering

- **Status:** Accepted
- **Date:** 2026-10-11
- **Deciders:** project owner
- **Packages:** all
- **Related:** [versioning-and-distribution.md](../architecture/versioning-and-distribution.md), OQ-3, OQ-7, roadmap Phase 6

## Context

Lua 5.5.0 was released on 2025-12-22 (5.5.1 since). It adds declarations of global
variables (`global`, `global <const> *`), read-only `for` loop variables, named vararg
tables, `table.create`, more compact arrays and incremental major collections.
LuaJIT (OpenResty) stays on 5.1 semantics. Supporting 5.4 and 5.5 simultaneously would
forbid 5.5 syntax and require compatibility shims. The owner expects 5.4 support to be
requested later.

## Options considered

1. **5.4 and 5.5 from the start.** No 5.5 syntax; shims for library functions; CI matrix
   doubled. Loses `global` declarations, which are the cleanest way to forbid implicit
   globals.
2. **5.5 only, forever.** Simplest; excludes users stuck on 5.4.
3. **5.5 only now; 5.4 later through mechanical source lowering.** Use 5.5 syntax only
   where a deterministic rewrite to 5.4 exists.

## Decision

Option 3.

- Every rock declares `lua >= 5.5, < 5.6`.
- Allowed 5.5-only constructs, each with its lowering:

  | 5.5 construct | 5.4 lowering |
  |---|---|
  | `global <const> *` / `global x` declarations | removed; strictness enforced by a test-time `_ENV` guard and the linter |
  | read-only `for` variables | no change needed (5.4 accepts the same programs) |
  | named vararg table `function f(...args)` | `local args = table.pack(...)` at function entry |
  | `table.create(n, h)` | `hecate.core.compat.table_create` (plain table on 5.4) |

- Any other 5.5-only feature requires amending this ADR.
- Library-level behaviour that differs between versions goes through
  `hecate.core.compat`, never through ad-hoc version tests.

## Consequences

- Modern code from day one; a 5.4 build remains feasible (Phase 6).
- Lua 5.5 may be missing from OS package managers: the CLI manages toolchains (ADR 0010)
  and Docker images ship it.
- Tooling must parse 5.5 (LuaLS supports Lua 5.5; StyLua to be checked, OQ-3).

## Verification

A CI job greps for forbidden constructs (task `check-lua-constructs`, see
[automation.md](../architecture/automation.md)). From Phase 6, the lowered tree is
tested on 5.4.
