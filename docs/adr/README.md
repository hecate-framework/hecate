# Architecture Decision Records

An ADR records one significant decision: its context, the options considered and the
consequences. ADRs are immutable once `Accepted`; a later ADR may supersede one.

- `Accepted`: binding. Code that contradicts it is a defect.
- `Proposed`: working hypothesis, drafted during design. Implement it as written; raise
  problems in [`../open-questions.md`](../open-questions.md) or by a superseding ADR.
  The project owner promotes it to `Accepted` after review.

Use [`template.md`](template.md) or the `/new-adr` command.
