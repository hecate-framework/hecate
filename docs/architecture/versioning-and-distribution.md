# Versioning and distribution

Status: specification; [ADR 0005](../adr/0005-single-brand-monorepo-lockstep-versioning.md)
(Accepted), [ADR 0010](../adr/0010-self-contained-cli-and-managed-toolchains.md) (Accepted).

## Versions

- Semantic Versioning 2.0.0, **lockstep** for all packages (`VERSION` file at the root).
- `0.x`: minor versions may break APIs; each break is listed in the changelog with a
  migration note. From `1.0`, breaking changes only in major versions.
- Rockspec revisions (`-1`, `-2`) are used only for packaging fixes.
- Development rockspecs: `scm-1`.

## Making the Lua version obvious

A user must know at a glance which Lua version a Hecate installation uses:

| Place | Shows |
|---|---|
| `hecate version` | Hecate, Lua, LuaRocks, libuv versions and platform |
| `hecate doctor` | the same plus compatibility warnings |
| Every rockspec | `lua >= 5.5, < 5.6` |
| README badge and website header | supported Lua line |
| Release notes | first line: `Hecate X.Y.Z — Lua 5.5` |
| Changelog headings | `## [0.3.0] — 2027-01-15 — Lua 5.5` |
| Docker tags | `hecate/runtime:0.3.0-lua5.5-debian` |
| Website | compatibility matrix page |

### Compatibility matrix (maintained in `website/en/reference/compatibility.md`)

| Hecate | Lua | Platforms | Status |
|---|---|---|---|
| 0.x | 5.5 | Linux, macOS, Windows (x86_64, arm64) | in development |

When 5.4 support arrives (Phase 6), the same Hecate version may support several Lua
lines; the matrix and `hecate doctor` state it explicitly. Artefact naming for 5.4 is
OQ-7.

## Repositories

Decided in [ADR 0017](../adr/0017-monorepo-with-read-only-mirrors.md). GitHub
organisation: [`hecate-framework`](https://github.com/hecate-framework). Website:
<https://hecate.theandre.dev> (provisional domain).

| Repository | Role | Writable |
|---|---|---|
| `hecate-framework/hecate` | monorepo: all development, issues, pull requests, CI, website, Docker, tools | yes |
| `hecate-framework/hecate-<name>` (one per package, e.g. `hecate-router`) | read-only mirror of `packages/<name>` with its own history and the same tags | no (split only) |
| `hecate-framework/homebrew-hecate` | Homebrew tap (formula for the CLI) | release pipeline only |
| `hecate-framework/scoop-hecate` | Scoop bucket (manifest for the CLI) | release pipeline only |

Mirror contents: the package directory at the mirror root (`README.md`, rockspecs,
`src/`, `csrc/`, `tests/`, `examples/`), plus files injected from
[`.github/mirror-template/`](../../.github/mirror-template/) (read-only notice,
pull-request auto-close workflow). `CLAUDE.md` files are kept in mirrors: they help any
agent reading the package.

Rockspec sources:

```lua
-- released rockspec (generated by `release prepare`)
source = {
  url = "git+https://github.com/hecate-framework/hecate-router.git",
  tag = "v0.3.0",
}
-- scm-1 rockspec
source = { url = "git+https://github.com/hecate-framework/hecate-router.git", branch = "main" }
```

The meta-rock `hecate` contains only re-exports and takes its sources from the monorepo
tag.

## Distribution channels

| Channel | Artefact |
|---|---|
| luarocks.org | one rock per package (`hecate-<name>`), meta-rock `hecate`, `hecate-cli` |
| GitHub Releases | CLI executables for linux/macos/windows × x86_64/arm64, checksums, SBOM, signatures |
| Installer scripts | `install.sh` (Linux, macOS), `install.ps1` (Windows) |
| Homebrew, winget, Scoop | CLI |
| Docker (Docker Hub and GHCR) | base images, see [`docker/README.md`](../../docker/README.md) |

## Docker images

| Image | Content |
|---|---|
| `hecate/runtime` | Lua 5.5, LuaRocks, libuv, OpenSSL, CA certificates; for running applications |
| `hecate/build` | runtime + compilers + headers + CLI; for building rocks and images (multi-stage) |
| `hecate/dev` | build + development tools (LuaLS, formatter); for dev containers |

Variants: `debian` (default, slim) and `alpine`. Architectures: amd64, arm64.
Tags: `<hecate-version>-lua<lua-line>-<variant>`, plus moving tags `<major.minor>`,
`latest` (debian). Images are rebuilt weekly for security updates and scanned in CI.

## Supply chain

- Release artefacts signed (Sigstore/cosign), SBOM (SPDX) attached.
- Checksums in the lockfile; `hecate install` verifies them.
- Reproducible builds as a goal for CLI binaries.
