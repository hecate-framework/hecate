# Documentation

Status: specification; [ADR 0012](../adr/0012-website-generator.md) (Proposed: site generated by
`hecate.doc` with an MDN-like theme; spike OQ-11 decides),
[ADR 0013](../adr/0013-english-code-multilingual-documentation.md) (Accepted).

## Two kinds of documentation

1. **Engineering documentation** (`docs/`): for contributors and agents. English only.
2. **Public website** (`website/`): for users. English source, translated.

Hosted at <https://hecate.theandre.dev> (provisional domain), deployed from `main` by
`website.yml`.

## Website structure (Diátaxis)

| Section | Purpose | Examples |
|---|---|---|
| Tutorials | learning by doing, reproducible verbatim | "Your first API", "A CRUD API with PostgreSQL" |
| How-to guides | solving one task | "Paginate a collection", "Deploy with Docker", "Add JWT authentication" |
| Reference | exhaustive, mostly generated | every package, class, function, CLI command, configuration key, error code |
| Explanation | concepts and rationale | concurrency model, suspension points, object model, data mapper, contracts |

Plus: migration guides between minor versions, glossary (public version of
`docs/glossary.md`), correspondence tables (relational algebra ↔ SQL; Hecate ↔ FastAPI /
Symfony / Express vocabulary), changelog, compatibility matrix.

The full site map is in [`website/OUTLINE.md`](../../website/OUTLINE.md).

## Generated reference

- Source: LuaLS annotations (`lua-language-server --doc` export, JSON) + route, schema
  and configuration metadata from the packages.
- Produced by `hecate doc` (Phase 3; a bootstrap script in `tools/` before that) into
  `website/en/reference/` as Markdown. Generated pages are never edited by hand; they
  carry a header comment saying so.
- Translations of generated pages translate only the prose parts (summaries,
  descriptions) through translation files keyed by symbol, not whole pages.

## Theme

One original Hecate theme for the website and for user projects (ADR 0012): MIT-licensed,
light and dark modes, WCAG 2.2 AA. No code or assets from Lua Web Docs (Tailwind UI
licence).

Owner direction of 2026-10-13 (ADR 0012 stays Proposed): `hecate.doc` is our own Lua 5.5
generator with a VitePress-like presentation and strict respect of the Hecate brand kit
(`tokens.json`, logo lockups, STIX Two / Fira Sans / Fira Code, nearly square corners, no
gradients or glows, the name never capitalised, earth as the single accent). Page chrome:

- top bar: logo, section links, search, locale switch, theme toggle, repository link,
  menu button on small screens;
- left sidebar (computed from the page tree or configured per section) and a right-hand
  "On this page" outline;
- previous/next cards, edit-this-page link, last-updated date, "written for hecate x.y and
  Lua 5.5" line;
- callout containers (`note`, `tip`, `warning`, `danger`), code blocks with a language label
  and a copy button, tables, task lists;
- search: one JSON index per locale, queried by about 150 lines of vanilla JavaScript.

Implementation and conventions: [`packages/doc`](../../packages/doc/README.md); open
choices OQ-33 to OQ-38. Build: `lua packages/doc/bin/build.lua website --strict` (bootstrap
runner until `hecate doc build`).

## Reference page template (MDN-like)

Inspired by Lua Web Docs (<https://luadocs.com>, "like MDN, but for Lua"). Every
reference page for a class or function follows the same sections, in this order:

1. One-sentence summary.
2. Syntax (signature, LuaLS-style types).
3. Parameters and return values (including `nil` for expected absence, ADR 0018).
4. Errors raised (classes and codes).
5. Whether it may suspend (`---@async`) and on which operations.
6. Examples (tested files, runnable when possible).
7. Specifications and standards implemented (RFC sections).
8. Compatibility: Hecate version introduced, Lua versions supported.
9. See also.

## Runnable examples (to evaluate, OQ-11)

Pure-Lua packages (`core`, `schema`, `router`, `query`) could run in the browser if Lua
5.5 is compiled to WebAssembly, letting readers edit and run examples on the page.
Anything depending on the reactor (libuv) cannot run in the browser and keeps static,
tested examples. The OQ-11 spike decides.

## Writing rules

- Every page states the Hecate version it was written for and the Lua version.
- Every code sample is a tested file under `packages/<name>/examples/` or
  `examples/`, included by reference, so samples cannot rot.
- Vocabulary from the glossary; first occurrence of a term links to the glossary.
- Short sentences, active voice, second person in tutorials and how-tos.

## Translations

- Locales: `en` (source), `fr` (first), more by contribution.
- `website/<locale>/` mirrors `website/en/`.
- Each translated page records the source revision it translates (front matter
  `source_revision`); `check-translations` flags stale pages.
- Untranslated pages fall back to English with a visible notice.

## LLM-facing documentation

- `llms.txt` (repository root and website root) lists the key pages with one-line
  descriptions; `llms-full.txt` concatenates the reference for ingestion.
- Every reference page has a stable anchor per symbol.

## Project documentation generated for users

`hecate doc build` on a user's project produces a static site with: the API reference
(OpenAPI, interactive), the code reference from the project's annotations, the
configuration reference, and the module/route map.
