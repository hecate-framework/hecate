## Responsibilities

- the tables that `hecate.unicode` needs, generated by `lua tools/run.lua gen-unicode` from `UnicodeData.txt` and
  `DerivedNormalizationProps.txt` of one pinned Unicode version, committed, deterministic: canonical combining classes,
  fully expanded canonical decompositions and primary composition pairs (the `Full_Composition_Exclusion` code points
  left out); Hangul syllables are not in the tables (algorithmic)
- the Unicode version (`unicode_version`) and the integer layout version (`format`) of the tables
- nothing else: no algorithm, no dependency, and no code other than the loader that returns the tables

## Non-goals

- compatibility mappings (NFKC, NFKD), case mapping, segmentation: additive later in this rock; each is a new ADR
- a mechanism to substitute the tables at run time

## Standards and references

- Unicode Character Database 18.0.0 (UAX #44), files `UnicodeData.txt` and `DerivedNormalizationProps.txt`
  (<https://www.unicode.org/Public/18.0.0/ucd/>), under the Unicode License v3
- Unicode Normalization Stability Policy (UAX #15, section 3)

## Licence and version

The tables are derived from the Unicode Character Database and are under the **Unicode License v3** (SPDX
`Unicode-3.0`), not the MIT licence of the rest of the framework: see [LICENSE](LICENSE) and the root
`THIRD_PARTY_NOTICES`. Every generated file starts with the notice. The generator is MIT.

The rock version is the **Unicode version** followed by a revision: `18.0.0-1` (the revision is for repackaging the same
Unicode version, such as a generator fix). This is an exception to the lockstep versioning of ADR 0005: the rock is
released on the Unicode schedule, `check-versions` and `gen-rockspecs` exempt it and the release of the framework does
not bump it. Its mirror tag is the Unicode version (`v18.0.0`). Publishing is an owner gate.

## Public API

All names are fields of `require "hecate.unicode_data"`. It is data for `hecate.unicode`; applications use
`hecate.unicode`.

| Name | Description |
|---|---|
| `unicode_version` | the Unicode version of the tables, a string such as `"18.0.0"` |
| `format` | the layout of the tables, an integer (`1`); `hecate.unicode` refuses a layout it does not know |
| `load(name)` | one table, loaded on first use: `"combining_class"` (flat triples `first, last, class`), `"decomposition"` (`[code point] = { code point... }`) or `"composition"` (`[first][second] = composite`) |

## Updating

Updating is a human step. The nightly job `unicode-version` fails when a newer version is published. Then: change the
URLs and SHA-256 values in `tests/external.lua` here and in `hecate-unicode`, run `lua tools/run.lua fetch-fixtures
unicode-data`, `lua tools/run.lua gen-unicode`, `lua tools/run.lua fetch-fixtures unicode` and the tests of `unicode`
(conformance against `NormalizationTest.txt`), raise the minimum in the `Depends on` row of `hecate-unicode`, then
release a new rock revision.
